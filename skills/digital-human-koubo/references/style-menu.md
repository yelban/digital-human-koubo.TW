# 剪輯風格選單（先選風格，再寫稿）

使用者把內容發過來以後，**先診斷內容，推薦 2 個風格，讓使用者選**；使用者點了風格再寫稿、切段、報價。同一份內容換風格，稿子的寫法、段落長短、全螢幕/小窗的比例、成本都不一樣，所以風格要最先定。

## 第一步：內容診斷（30 秒內給結論，不用問使用者）
讀完使用者的內容，寫一行診斷：

> 「這是一條 **產品推薦**（第一人稱體驗、要號召下單），素材裡有 **3 個作品可展示**，適合 **直式 60–90 秒**。」

看這幾樣：
| 訊號 | 指向 |
|---|---|
| 有事件 / 資料 / 時間線 / 「為什麼」「怎麼回事」 | A 小林式解說 |
| 第一人稱安利、帶貨、種草、吐槽、號召 | B 網紅花字口播 |
| 新品 / 新模型 / 新功能發布，有官網、參數、對比 | C 發布解讀 |
| 「怎麼做」「幾步」、有操作介面、命令 | D 保姆級教學 |
| 要多語言、多場景、多個角色或使用者本人出鏡 | E 多主播接力 |
| 平台是抖音 / 小紅書 / 視頻號 | 直式優先（B），其他風格也可以出 9:16 版 |
| 平台是 B 站 / YouTube / 公眾號影片 | 橫式優先（A / C / D / E） |

## 第二步：給使用者選
在 Claude Code 裡用 AskUserQuestion（一次最多 4 個問題），**第一個選項寫推薦理由並標「推薦」**；其他工具（Codex 等）就列編號讓使用者回覆數字。同時把對應預覽圖發給使用者看（`assets/styles/*.jpg`，SendUserFile）。

一次問完，別來回問：
1. **風格**：推薦的 2 個 + 「其他風格」（列出剩下的名字）
2. **比例和時長**：例如「9:16 · 約 60 秒（推薦）」/「16:9 · 約 3 分鐘」/「兩個都要」
3. **花字強度**（只對 B，其他風格可略）：克制 / 標準（推薦）/ 熱鬧
4. **主播**：白背心數位人 / 使用者本人的數位人 / 兩位接力 / 動物角色

使用者回「都行」「你定」時就按推薦走，並在回覆裡寫一句「按推薦：B · 9:16 · 標準」。

選完把結果寫進工程目錄 `brief.json`：
```json
{ "style": "B", "ratio": "9:16", "length_s": 60, "huazi": "標準", "host": ["tank"], "languages": ["zh"],
  "platform": "抖音", "cta": "去試試 Renoise", "showcase": ["show/a.mp4"], "notes": "使用者說別太吵" }
```
後面的寫稿、切段、剪輯全按 brief.json 來；使用者中途改主意就改這個檔案。

## 五種風格

### A · 小林式解說（財經 / 科技事件）
![](../assets/styles/A_xiaolin_explainer.jpg)
- **適合**：一件事講清楚——暴雷、收購、行業格局、「為什麼 XX」。3–20 分鐘。
- **畫面**：主播全螢幕 ↔ 縮成小窗、旁邊上圖表 / 檔案標黃 / 時間線 / 競猜；章節標題卡；擬人貼紙獨白。每分鐘 9–12 次畫面切換，主播全螢幕一次不超過 12 秒。
- **稿子**：三種骨架（危機型 / 博弈型 / 悖論型），每分鐘 1–2 個設問、3–4 個帶參照物的數字；至少 3 個活人感手法（替觀眾質疑、生活比喻、坦白沒查到、先說答案…）。
- **怎麼做**：走 `finance-explainer` skill 的流程和引擎（`~/.claude/skills/finance-explainer`，episode.json 拍表驅動）；主播用本 skill 的數位人，口播段按 15 秒切。
- **紅線**：只學結構和手法，不用小Lin本人的臉、聲音、佈景、口頭禪原句；每個數字進 facts.md 帶出處。
- **預設包裝**：開場砸字/搜尋框 → 證據截圖 → 主問題 → 第一章；全片進度條 + 出處角標 + 每章復盤板；數字用 Counter、原文用 DocFocus、地點用 MapRoute、揭曉前 PollPop。
- **成本**：小窗段多（約 60%）→ 大量 480p，比同長度的全螢幕口播便宜約三成。

### B · 網紅花字口播（直式）
![](../assets/styles/B_huazi_koubo.jpg)
- **適合**：產品安利、帶貨、種草、觀點吐槽、起號。30–120 秒。
- **畫面**：主播直式全身 / 半身；逐字彈跳字幕 + 關鍵詞變色放大；臉兩側彈動態表情；跳切交替推近 + 重點詞推一下；蓋章、砸屏大字、對比條、清單卡；展示作品時主播縮右下小窗；結尾號召大字。
- **稿子**：開頭 3 秒鉤子（反問 / 反常識 / 數字），一段一個點，口語、短句，結尾明確號召。
- **怎麼做**：`templates/huazi-916`（資料驅動，改 edit.json 就行），詳見 references/huazi.md。
- **花字強度**：克制（知識類、品牌號）/ 標準（大多數）/ 熱鬧（搞笑、帶貨、年輕向）。
- **預設包裝**：0–2 秒數字釘子或傾斜金句 → 彈幕替觀眾質疑 → 關鍵詞三連；每 3 秒一個刺激點，截圖用直式 ZoomFocus，中段 0.5 秒故障插屏號召。
- **成本**：全螢幕 720p 為主（每秒約佔 grok 每週額度 0.25–0.35%）。

### C · 發布解讀（橫式側邊講解）
![](../assets/styles/C_launch_side.jpg)
- **適合**：新模型 / 新產品 / 新版本發布，30–90 秒的快訊解讀。
- **畫面**：開頭 3 秒快閃砸字；主播直式放左側，右側放程式碼動效 / 參數氣泡 / 對比卡 / 官網截圖；結尾金句 + 連結。
- **怎麼做**：參考實現 `templates/reference/launch-169/src/Film.tsx`（人物卡居中 ↔ 側邊彈簧縮放 + 5 場 B-roll）。內容場景每期重寫。
- **預設包裝**：產品冷鏡頭 + 主題句 → 關鍵詞三連 → 里程錶 / 玻璃面板 / 官方文件一個證據 → 反轉 → 4–8 秒片頭；主播多檔景別跳切，參數用 SpecCard。
- **成本**：中等，主播全程出鏡但多為 480p 側邊。

### D · 保姆級教學（橫式）
![](../assets/styles/D_tutorial.jpg)
- **適合**：「幾步做出 XX」、工具上手、安裝配置。3–8 分鐘。
- **畫面**：頂部步驟進度條；左側介面模擬（瀏覽器 / 終端 / 聊天窗逐字打出、橙色圈出按鈕）；主播在右側小窗，講概念時全螢幕；插入真實演示對比片段。
- **稿子**：每步「做什麼 → 怎麼點 → 怎麼確認成功」，命令寫成好唸的樣子，真實數字（價格、積分）進畫面。
- **怎麼做**：參考實現 `templates/reference/tutorial-169/src/Tutorial.tsx`（tl.json 驅動，每段一個 Scene）。
- **預設包裝**：搜尋框打字開場 → 成品快閃 → 步驟徽章常駐；每個「點哪裡」用 ZoomFocus + 手繪圈，坑用 FreezeFrame「等等！」，每大步後復盤板。
- **成本**：pip 段 480p，最省。

### E · 多主播接力 · 多語言 · 多場景
![](../assets/styles/E_multi_host.jpg)
- **適合**：展示數位人能力本身、品牌出海、一個產品多場景（直播帶貨 / 廣告 / 導覽 / 講師）、動物角色、使用者本人出鏡。
- **畫面**：冷開場多語言快閃（一句整句 + 五語各 1 秒問候）；兩位主播橫豎混排接力；全螢幕場景片段帶語言標籤和中文翻譯；結尾快閃 + 同框。
- **怎麼做**：參考實現 `templates/reference/multihost-169/src/Tutorial.tsx`（nar / clip / title / outro 四類條目）。場景圖先用 grok 的 image_edit 合成（人物參考圖 + 場景描述），在 script.json 那幾段寫 `"ref"` 當參考圖，再交給 Grok 開口。
- **坑**：Grok 橫式口播偶爾自己燒字幕，生成完抽幀檢查；外語台詞提前翻好，生成後按語言回聽；冷門漢字讀音（如日語「提燈」）可能唸錯。
- **預設包裝**：多語言快閃 / 預告閃回 → 逐詞堆疊 → 標題卡；換主播打字名牌，去過哪兒用地圖航線，換場景用對比擦除或紙張拼貼。
- **成本**：最高——場景圖 + 全螢幕 720p 多。

## 包裝
每種風格都自帶一套預設包裝（上面每節的「預設包裝」，完整配置在 references/packaging-presets.json）。問使用者時可以加一題「包裝節奏」：克制（MKBHD 式，字少留白）/ 標準（推薦）/ 快節奏（MrBeast 式，每 3 秒一個刺激點）。

## 組合
- 同一條內容可以「A 橫式長版 + B 直式切片」一起出：先做 A，再從裡面挑 3–4 段最有衝擊的口播套 B 模板（口播片段不用重拍）。
- 使用者只想先看效果：先拍第 1 段 + 用 B 模板出 15 秒樣片，確認後再批次。
